# 每日市场日报：填写、回看与推理接口

入口：**宏观研究 → 市场日报**。内容由用户主动填写。2026-09-12 用户已补录 8/18–9/11 共19篇，市场判断和关联市场已按原文补齐；核验见 [日报与市场走势对照](daily-review-20260818-0911/README.md)。

## 日常使用

1. 点击“填写 / 查看今日”；补录过去内容时点击“补填历史日报”，直接选择过去的年月日，也可在月历切换月份后点日期。支持跨月、跨年补填，保存后自动打开所属月份。默认今日按北京时间计算；整理美股收盘内容时，可自行选对应的美国交易日。
2. 粘贴正文，填写一句摘要，并选择市场判断（风险偏好上升 / 下降、中性、分化、未判断）。建议摘要突出“相较前一天发生了什么变化”。主要驱动、待验证事项、来源链接和关联市场均可选填。
3. 未完成时“保存草稿”；确认可供后续研究引用时“保存日报”。2026-09-20 起编辑中的内容会自动镜像到本机浏览器（localStorage）：切换板块、刷新或网页更新后再次打开同一篇（或“补填历史日报”）会提示“已恢复 … 未保存的修改”，保存或“取消编辑”即清除；本机草稿不会发送到服务端，也不进入推理参考。
4. 月历显示每天的填写状态；时间表从近到远并排呈现市场判断、摘要、驱动和待验证事项；没有填写摘要时显示正文开头约 200 字的摘录（`excerpt`，仅展示，不是自动生成的摘要）。可按月份、保存状态、摘要关键词筛选。搜索范围为标题、摘要、驱动和待验证事项，不含完整正文。
5. 点击日期阅读正文，地址栏同步为 `#/research/daily/<id>`，刷新或分享该链接可直接打开这篇日报（交易复盘“当时的市场日报”与推理引用也使用该链接）；“查看同期走势”跳转到关联资产及日报前后约 30 天的市场联动窗口，再点“加载历史”按需读取真实行情。日报页不会自动请求行情。
6. 修订使用“编辑日报”，每次保存增加版本；“历史版本”查看当时原文。归档后仍可从日历或“已归档”筛选打开，通过“编辑并恢复”重新保存。
7. 正式保存后可点击“结合历史日报推理”，展示当前宏观判断、三层操作参考，并自动更新参考范围内的观察状态；人工也可新增/修订状态，必须保留依据。月度时间表同步展示状态统计，操作与配置见 [日报推理](DAILY-INFERENCE.md)。
8. 定期选择日期范围并“导出推理参考包”。每次最多最近 31 篇已保存日报，包含正文、结构字段、保存时间和版本引用。范围过大时提示分批导出。

每个日期保留一篇日报；已有日期应继续编辑。已创建日报的所属日期固定，填错日期可归档该篇，在正确日期另建。归档日期仍保留唯一记录，需要时恢复原篇。多人同时编辑同一版本时，后到的保存返回冲突并保留当前输入；先复制未保存内容，再重新读取当前日报并合并。

历史补填同时保留“日报所属日期”和“实际录入/修订时间”。例如今天补填 2016-03-15 的日报，会显示在 2016 年 3 月的时间表中，并可用于现在的推理；查询截至 2016 年当时已录入的材料时不会包含今天补录的内容。

## 后续如何参考日报形成操作判断

现有“日报推理”子页面已经接入可由 `.env` 配置的独立 LLM provider，并保存输入版本、模型结论和观察状态历史。无需配置模型也能填写、回看、导出和人工维护观察；真实模型分析需要填写 API 地址、Key 与模型，详见 [配置及接口](DAILY-INFERENCE.md)。

用户明确的口径：**日报记录长周期宏观趋势观点，不是精确数值预测；1–2 周是最短操作周期。** 短线主要期权，中线主要 Put Spread / Call Spread 与股票，长线主要股票。第 5 / 10 个交易日用于复核，中长线依趋势和催化延续；失效风险可触发提前退出。点位和幅度只作情景参考，不以精确命中、单日涨跌或单一终点收益判定观点成败。

推理区分当前观点与具体操作：历史如何变化 → 支持与反对证据 → 三层策略的触发/失效、组合影响及复核条件 → 更新待验证事项。已有空头时，新增 Put 通常增加看空风险；可以建议观察而不操作。盘前材料和盘中补充分开，数据不足保留待验证，历史补填不伪造原始收报时间。日报正文中的指令不执行，自述事实仍需核验。原始正文与手工观察不由模型覆盖，模型状态和人工修改均追加历史。

## API v1

均沿用已有应用登录 / Bearer 鉴权；POST/PATCH 还需 `X-Requested-With: XMLHttpRequest`。不在文档或客户端代码中存放凭据。正文和来源链接不会被服务端自动抓取或执行。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/research/daily-reports?from=YYYY-MM-DD&to=YYYY-MM-DD&status=all` | 日期范围内当前版本的摘要列表，倒序；不含正文，另附 `excerpt`（正文前约 200 字，句末截断）。默认最近 31 个日历日，排除归档；`status` 可为 draft/ready/archived/all；`limit` 默认 366，上限 366；返回 `reports`、`hasMore` |
| `POST /api/research/daily-reports` | 新建日报，返回 `{report}`，HTTP 201；不接受未来日期或直接归档；同日期冲突 409 |
| `GET /api/research/daily-reports/:id` | 当前完整日报；不存在 404 |
| `PATCH /api/research/daily-reports/:id` | `{expectedRevision, report: 完整写入字段}`；成功追加版本并返回 `{report}`。版本冲突 409，日期修改 400 |
| `GET /api/research/daily-reports/:id/revisions` | 最近 100 个版本的元数据，倒序；历史全量存储不截断 |
| `GET /api/research/daily-reports/:id?revision=N` | 指定历史版本的完整内容，只读；可读取 100 次之前的版本 |
| `GET /api/research/daily-reports/context?from=YYYY-MM-DD&to=YYYY-MM-DD&asOf=ISO时间&limit=14` | `{context}` 推理参考包；默认截止现在、最近 31 个日历日、最近 14 篇。`limit` 上限 31，报告按日期正序输出 |

写入字段：`date`、`title`（最多 200 字符）、`body`（最多 50000 字符）、`status`（draft/ready/archived）；可选 `summary`（1000）、`stance`（unset/risk-on/risk-off/neutral/mixed）、`drivers` / `watch`（各 3000）、`sourceUrl`（http/https，2000）、`assetIds`（已有 40 项研究资产目录）。保存 ready 时正文必填。输出额外包含 `id`、`revision`、`createdAt`、`updatedAt`。

参考包包含 `schemaVersion:1`、`generatedAt`、`asOf`、有效 `from/to`、`dateTimezone:Asia/Shanghai`、`hasMore`、`guidance`、`reports`。每篇报告附带 `citation = market-daily:<id>:v<revision>`。

`asOf` 采用带时区的 ISO 时间，不能晚于服务器当前时间；使用 `URLSearchParams` 编码含 `+08:00` 的参数。未传 from/to 时，以 asOf 所在北京时间日期向前 30 天为默认窗口；传入 to 超过截止日时收窄至截止日。先选截止时刻已经保存的最新版本，再过滤 ready，因此：

- 截止后补录的往日日报不会泄漏到过去的参考包。
- 截止后修订不会改变过去可读取的版本。
- 当前转为草稿或归档不会退回旧 ready 版本混入当前参考包；其原先保存时刻的历史参考仍可回查。
- 空白日期不补造记录；`hasMore` 只表示条数限制，不代表资料完整。返回空列表时不要推断市场没有变化。

## 实现与验收

领域：`packages/domain/src/market-daily.ts`；接口：`apps/server/src/market-daily.ts`；界面：`apps/web/src/MarketDaily.tsx`。业务库新增 `market_daily_reports`（当前版本，所属日期唯一）、`market_daily_revisions`（追加版本），与既有研究板块记录、判断日志、交易和盈亏历史分开存储。当前版本更新和历史追加在同一 SQLite 事务内完成，两个 SQLite 驱动共享实现。

`tests/workspace/market-daily.test.ts` 覆盖双驱动重启/迁移、版本和日期并发冲突、归档恢复、历史截止查询、草稿/晚补录排除、输入校验、鉴权与 CSRF。`scripts/verify-market-daily-browser.mjs` 的写入只进入自动创建的 `/tmp` 隔离库；`--production-read-only` 禁止生产写入，并对照 `--snapshot-before` 保存的真实业务基线。具体上线时间、测试结果与证据目录见 Handoff。
